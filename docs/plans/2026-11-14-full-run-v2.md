# Full Run v2 Implementation Plan

**Goal:** Prepare a second measured self-improvement experiment, starting from the calibrated harness, with fresh held-out cases, a doubled reference baseline, a noise-aware promotion rule, and a miner that can see request-budget exhaustion and repeated reads, frozen and ready to start but not started.

**Architecture:** A new manifest scoring version, `pooled-margin-v1`, measures the reference version (the initial baseline, or the last promoted candidate) with 6 trials per selection case and each candidate with 3. A pure decision function promotes a candidate only if it beats the pooled reference by more than a noise margin, which is measured once from the two halves of the initial baseline and clamped to 2–4. The old `per-case-count-v1` path stays byte-for-byte compatible for the full-run-v1 ledger. The case miner gains two harness-computed "signal" rows per failed attempt that the diagnosis can cite and that group into leads. Fresh selection-validation and final-test cases are drawn deterministically from SWE-bench Verified, admitted with empty and reference grading, and frozen with the existing development cases into `data/self-improvement/full-run-v2`.

**Tech stack:** Python 3.13, pydantic, SQLite via the existing `ExperimentStore`, pytest (asyncio, xdist), ruff, mypy, `uv`, Docker (image inspect/pull and admission grading only), git sparse checkout of `SWE-bench/swe-bench-tasks`.

**Spec:** Decisions agreed with the operator on Nov 13–14, 2026 (summarized below), the handoff `docs/self-improvement-handoff.md` §4, and the calibration results in `docs/plans/2026-11-13-solver-pacing.md`.

### Agreed decisions

- **Cases:** keep the 5 full-run-v1 development cases (`sympy__sympy-18199`, `scikit-learn__scikit-learn-12682`, `sphinx-doc__sphinx-10323`, `pytest-dev__pytest-10051`, `astropy__astropy-13579`). Draw 10 fresh cases from the same five repositories: one selection-validation and one final-test case per repository. Retire the old selection-validation and final-test cases.
- **Harness under test:** the calibrated harness at the current `main` (solver pacing, budget-paced projection, `edit_file`). The six editable files must be identical to commit `9ad0a5f` when the experiment is frozen.
- **Reference measurement:** the reference version gets 6 trials per development and selection-validation case, as two halves of 3 (repeat indexes 0–2 and 3–5). Candidates get 3. A promoted candidate is topped up to 6 before the next round.
- **Noise margin:** `margin = clamp(|half_a − half_b|, 2, 4)`, where each half is the total passes over the 10 selection cases for repeats 0–2 or 3–5 of the **initial** baseline. Record it once, before the first mining, and never recompute it. Record a noisy-baseline warning when the gap exceeds 4.
- **Promotion rule** (all must hold; the baseline count `R` is out of 6, the candidate count `C` out of 3):
  1. Checks pass and all 30 candidate trials are graded (unchanged from today).
  2. Overall gain: `2·ΣC > ΣR + 2·margin`, i.e. the candidate total beats the reference average by more than the margin.
  3. Validation: `2·ΣC_val ≥ ΣR_val`, i.e. no loss on selection-validation.
  4. No large per-case drop: for every case, `R − 2·C < 4`, i.e. the drop is under 2 passes.
  The candidate must also differ from the reference (`no_change` rejection unchanged).
- **Final test:** unchanged. 3 trials per final case for the original and the selected version, reported side by side; it does not gate anything.
- **Miner:** add the `budget_exhaustion` and `repeated_reads` labels.
- **Token cap:** a safe ceiling for the whole run (see Task 9): 55,000,000 tokens against a worst case of 240 trials at the 200k per-trial cap plus roles. The expected spend is about 30–35M.
